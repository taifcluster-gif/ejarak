# إدارة العمارة (Building Manager)

تطبيق عربي / إنجليزي لمالك عمارة يتابع الشقق والمستأجرين والعقود والدفعات والعدادات. يشتغل بدون إنترنت، وبياناته محفوظة على جهاز المستخدم. يعمل كموقع PWA وكتطبيق أندرويد (Capacitor) مع تذكيرات مجدولة.

## 1) نسخة الويب (GitHub Pages)
ارفع المجلد كله على GitHub، وفعّل Pages من Settings ← Pages (Branch: main، Folder: root). افتح الرابط من الجوال واختر "إضافة إلى الشاشة الرئيسية".
عند تعديل أي ملف غيّر رقم `VERSION` في `sw.js` عشان يتحدث عند المستخدمين.

## 2) تطبيق الأندرويد (APK عبر GitHub Actions)
ما تحتاج تثبّت Android Studio. الـworkflow في `.github/workflows/android.yml` يبني التطبيق على سيرفرات GitHub:

1. ارفع المشروع على مستودع GitHub (نفس المستودع تبع Pages ينفع).
2. روح تبويب **Actions** ← **Build Android APK** ← **Run workflow** (يشتغل تلقائياً عند كل push على main).
3. بعد دقائق نزّل الملف من **Artifacts** (`building-manager-debug-apk`) وثبّته على الجوال (فعّل "التثبيت من مصادر غير معروفة").

الـworkflow يسوي: `npm install` ← اختبارات المنطق ← نسخ ملفات الويب إلى `www` ← `cap add android` ← توليد أيقونات التطبيق من `assets/` ← أيقونة الإشعار وتعديل المانيفست ← `cap sync` ← `gradlew assembleDebug`.

### قبل النشر على Google Play
- **غيّر `appId`** في `capacitor.config.json` (الحالي `com.usefultech.buildingmanager`). بعد أول رفع على Play ما ينغير.
- ملف الـAPK أعلاه تجريبي (debug). للنشر تحتاج AAB موقّع (release) بمفتاح توقيع تحتفظ فيه: أضف الـkeystore كـSecrets في GitHub وخطوة `bundleRelease` في الـworkflow.
- رقم الإصدار (`versionCode` و`versionName`) يرتفع يدوياً مع كل نسخة جديدة.

### التذكيرات (الإشعارات المحلية)
- تُجدول على الجهاز نفسه (بدون خادم). قبل الاستحقاق بعدد الأيام المحدد في الإعدادات، ويوم الاستحقاق، وبعده بيوم وبأسبوع، وقبل انتهاء العقد بـ60 و30 و7 أيام، وتذكير بقراءات العدادات يوم 25.
- الأفق 90 يوم وحد أقصى 60 إشعار، وتُعاد الجدولة تلقائياً عند كل تعديل في البيانات وعند فتح التطبيق. لو ما فتحت التطبيق أكثر من 90 يوم ما تجي تذكيرات جديدة.
- التنبيهات غير دقيقة بالدقيقة (قد تتأخر دقائق لتوفير البطارية)، وحذفنا صلاحية المنبّه الدقيق عمداً عشان Google Play ما يطلب نموذج تصريح.
- الدفعة التي تنسدد تختفي تذكيراتها عند الحفظ.

### داخل التطبيق الأصلي
التنزيل المباشر ما يشتغل داخل WebView، فالتصدير (CSV) والنسخة الاحتياطية وسند القبض تفتح قائمة المشاركة (واتساب، ملفات، بريد...). زر الرجوع في الجوال يغلق النافذة، ثم يرجع خطوة، ثم يخرج.

## هيكل الملفات
| الملف | وظيفته |
|---|---|
| `js/logic.js` | كل المنطق بدون واجهة: جدولة الدفعات، الحالات، الإحصائيات، التنبيهات، خطة الإشعارات، CSV، واتساب |
| `js/store.js` | طبقة التخزين. اليوم `localStorage`، وتقدر تبدلها بـ adapter سحابي |
| `js/i18n.js` | كل نصوص الواجهة بالعربي والإنجليزي. لإضافة لغة أضف كائناً جديداً وخيارها في الإعدادات |
| `js/ui.js` | أدوات الواجهة: تنسيق، أيقونات، نوافذ، نماذج |
| `js/views.js` | الشاشات والإجراءات ومعالجات النماذج |
| `js/native.js` | طبقة الأندرويد: إشعارات، مشاركة ملفات، زر الرجوع (لا تفعل شيئاً في المتصفح) |
| `js/main.js` | التشغيل وربط الأحداث واللغة والمظهر |
| `css/style.css` | الألوان (متغيرات في أول الملف) والتنسيق، فاتح وداكن، عربي وإنجليزي |
| `capacitor.config.json`, `scripts/`, `native-res/`, `assets/` | مشروع الأندرويد |
| `tests/logic.test.js` | اختبارات المنطق (`npm test`) |

## قرارات مصممة للتوسع
- **معرّفات UUID** لكل سجل بدل أرقام متسلسلة، فيمكن دمج بيانات من أجهزة أو مستخدمين بدون تعارض.
- **`ownerId` موجود في كل جدول** (ملاك، عمارات، وحدات، مستأجرون، عقود، فواتير). اليوم مالك واحد، وتعدد الملاك يحتاج واجهة فقط.
- **عدة عمارات** مدعومة في هيكل البيانات (`buildings`). الواجهة الحالية تعرض الأولى.
- **طبقة تخزين قابلة للتبديل**: اكتب adapter فيه `load()` و`save(db)` ثم `RA.store.use(adapter)`.
- **ترقية البيانات**: `schema` في كل نسخة، وأضف دالة في `MIGRATIONS` عند تغيير الهيكل.
- **النسخ الاحتياطي JSON** يحمل رقم الإصدار ويُرجع بدون فقدان.
- **حالة الدفعة** (مسددة، متأخرة، قريبة...) تُحسب من التاريخ والمدفوع ولا تُخزن، فما تتعارض مع الواقع.

## نموذج البيانات (مختصر)
```
db = { schema, settings, owners[], buildings[], units[], tenants[], contracts[], bills[] }
contract = { id, ownerId, unitId, tenantId, start, months, annualRent, freq, deposit, ejarNo,
             terminatedAt, installments: [ { id, no, dueDate, amount, payments: [ {date, amount, method, receiptNo} ] } ] }
```

## المرحلة القادمة (مقترحة)
حسابات وتخزين سحابي، أدوار (مالك، مدير، محصّل)، توقيع release لـPlay، تقرير سنوي PDF، مرفقات (صورة العقد والهوية)، مصروفات العمارة، شاشة عرض أكثر من عمارة.
